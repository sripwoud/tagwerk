# A rename folds a retired project name into its current one

Renaming a project directory splits it in two: `resolve_cwd` derives the project from the path at report time, so events written before the rename keep deriving the old name forever. `carpinteria-aluminio-landing-page` moved to `ma-instalaciones` with 255 events behind it, and September's table was about to grow a second row for one project. The same split on a `work` root emits two line items from `render_invoice`, in a table a customer reads.

A `[rename]` table in the config maps a retired project name to its current one, applied at resolution. clig.dev sorts configuration by stability -- frequently changing settings want flags, settings that vary by user want environment variables, stable ones want a command-specific file -- and a rename is the most stable fact this tool holds: written once, never revisited. It joins `[roots]` and `[[title]]`, the two rules that already own project derivation.

The rule keys on the project name rather than the old path, because paths reach one of three bucket sites. `resolve_title` extracts a project from a GitHub window title and a renamed repo renames the title too; a span stores `"project": "groups"` with no path at all, and 202 of them sit in the ledger from the timew import. One name-keyed entry folds all three. A rename never touches the kind: kind is a property of where the work happened, and where it happened is a historical fact. A config edit that could retroactively turn `personal` minutes into `work` minutes would put invented hours on an invoice already sent (ADR-0006).

Rejected: a `rename` event in the ledger, which would travel with the data and need no config. A rename is timeless and the minute walk consumes events in order, so it could not be read by the `applied` pointer -- it would need a second traversal, a new event type and a new command, to hold a fact with one writer and one reader. Rejected: rewriting the month files, which ADR-0002 forbids outright. Rejected: deriving the project from the git remote, stable across a directory rename but not across the GitHub rename that accompanied this one, at the price of a subprocess on every beat and poll, and still leaving the 255 existing events split. Rejected: a `tagwerk rename OLD NEW` command that edits the config, because `tomllib` reads TOML and nothing in the stdlib writes it, ADR-0004 forbids the dependency that would, and blind-appending to a file the user comments by hand is the boundary crossing clig.dev warns against. Every other derivation rule here is hand-edited.

Consequences: the fold happens at all three bucket sites rather than where minutes are credited, because `leases` is keyed by bucket and ADR-0003 splits each present minute by the number of leases. Folding after the split counts an old and new pair as two repos: with one other repo also leased, the renamed project would take two thirds of the minute instead of half. `load_config` refuses a catch-all on either side -- a target of `general` would flip `is_repo` and silently convert a leased repo into an ambient bucket -- and refuses a chain, so `a = b` beside `b = c` is an error naming its own fix rather than a half-applied fold. A rename has no cutoff date, so a retired name can never be reused by a different project; pick another name. Two repos that share a directory name under different roots fold together, which repo naming makes unlikely and nothing detects.
