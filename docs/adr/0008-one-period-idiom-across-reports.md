# One period idiom across the report commands

The four report commands each selected their period differently: `today` not at all, `week` with `-n N` weeks back, `month` with an optional `YYYY-MM`, `invoice` with a required one. Four commands, four idioms, and `-n` had no long form while clig.dev reserves that short name for `--dry-run`. Every report now takes an optional period argument in its own unit — `day [YYYY-MM-DD]`, `week [YYYY-Www]`, `month [YYYY-MM]`, `invoice [YYYY-MM]` — plus `--ago N` counted in that same unit, and argparse rejects giving both. `today` is renamed `day`, the word the code already used everywhere internally (`credited_days`, `day_cap_h`, `local_day`); a command named `today` cannot honestly take a date.

`invoice` gains a default and it is the current month, matching `month`. It prints a markdown table to a terminal and sends nothing to anyone, so reading a part-finished month is a legitimate question and a partial month is visibly partial. Rejected: defaulting to the previous month, which fits the billing habit but makes `month` mean current and `invoice` mean previous — a third rule wearing consistency's clothes.

Rejected: positional only, which retires `-n` cleanly but turns the most-typed relative query into `week 2026-W36`, requiring you to look up a week number to ask how last week went. Rejected: `--ago` only, which loses `invoice 2026-08` — absolute selection is the entire point of the invoice command. Rejected: one positional accepting either form, disambiguated by shape (`week 1` versus `week 2026-W36`), because `day 1` is genuinely ambiguous between the first of the month and yesterday. The two-spelling objection to the chosen shape dissolves once they are mutually exclusive: each invocation has exactly one meaning, and each spelling owns a distinct job.

Consequences: `-n` is retired with no alias and `--ago` takes no short form, leaving the short namespace empty so the next reserved-letter collision cannot happen. `today` is gone rather than aliased. `date.fromisoformat` parses `YYYY-Www` and `YYYY-MM-DD` natively and rejects `2026-w36` and `2026-9-01` on its own. It takes both forms, though, so it cannot tell a day from a week: each unit gets a one-line parser instead. The day form guards against the `W` shape, the week form appends `-1`, and the month form appends `-01` as it already did. Strictness still costs nothing, because no parser checks a range or a spelling itself. Future periods render empty rather than erroring: an empty week is a visibly zero answer, not a wrong one, and the current month is already part-future so any no-future rule needs an exception on day one. `month` and `invoice` now differ only in rendering but stay separate commands — they answer the burnout question and the billing question, and ADR-0006 exists because those two consumers once stopped agreeing.
