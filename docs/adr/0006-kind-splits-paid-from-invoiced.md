# Kind splits paid from invoiced, and never names the payer

A second customer pays for fixed-price work, so its hours belong in the burnout check but not on anyone's invoice. `work_minutes` and `render_invoice` both filtered `kind == "work"`: one predicate serving two consumers that had quietly stopped agreeing. `kind` gains `fixed` — paid, charted, never invoiced — so the caps count `work` and `fixed` while the invoice counts `work` alone.

Rejected: `kind` as the payer (`exodus`, `carpinteria`), which reads wrong at every call site and splits a customer's history in two the day a stream is renamed, since spans freeze their kind and ADR-0002 forbids rewriting them. Rejected: a `customer` field on `Bucket`, which stores one fact twice, because paid is true exactly when a customer is set. Rejected: an `[invoice] exclude` list of projects, which is enumeration-scoped where every other rule in the config is territory-scoped, so it silently rots the first time a client gains a second repo.

Consequences: `off` in a root or title rule is now rejected at config load. It was accepted and ignored — only the span path checked it — and honouring it instead would erase minutes the user was present for, breaking the wall-clock guarantee ADR-0003 rests on. The `today` and `month` tables print `kind/project`, the notation the docs already use, so two kinds can no longer both render a bare `general` row. `fixed` draws from the same palette as `work` because the bars answer the burnout question, where the two are identical. A second customer invoiced by the hour is still unmodelled; that is the trigger to revisit, not before.
