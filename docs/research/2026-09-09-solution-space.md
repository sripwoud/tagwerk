# tagwerk: solution space review

_Research against primary sources and the local machine (lechuck), 2026-09-09. Read-only except this file. Plan under review: `/home/sripwoud/code/tagwerk/plan.md`._

## 1. Verdict

The plan is sound. Sensors, store, interpreter choice and the even-split attribution hold up against the sources. Nothing off the shelf covers passive per-repo attribution on Hyprland with CLI corrections.

Changes ranked by value:

1. Replace the `/proc` walk with `kitten @ --to unix:$XDG_RUNTIME_DIR/omarchy-kitty-<pid> ls`. Omarchy 4 ships `/etc/xdg/kitty/kitty.conf` with `allow_remote_control socket-only` and that `listen_on`; verified working from a non-kitty environment. Tab-aware, removes the section 13 "one shell per kitty" ceiling.
2. Set the hypridle listener timeout to 150 s, matching Omarchy's screensaver stage, or treat focus class `org.omarchy.screensaver` as absent. With 300 s, minutes 2.5 to 5 of every idle period land on `personal/other`.
3. Add `before_sleep_cmd = tagwerk idle` and `after_sleep_cmd = tagwerk active` to `hypridle.conf`. Free explicit suspend marks from logind; the heartbeat gap stays as the safety net.
4. Add `sudo rm /usr/lib/systemd/system-sleep/timew-stop` to the section 12 cleanup. Unowned leftover that runs `timew stop` as your user on every suspend.
5. Fix two section 1 claims: wakapi does not sum concurrent projects (it groups heartbeats sequentially by a project hash), and ActivityWatch does accept CLI edits (REST `POST /api/0/buckets/<id>/events`). The rejection still stands for other reasons.

Leave alone: JSONL store, `#!/usr/bin/python3 -I`, the 15 s poller (socket2 cannot see `cd` inside a window), hypridle over Omarchy's shell IPC, the even-split minute model, Claude hooks including `PostToolUse *`.

## 3. Solution space

### ActivityWatch, awatcher, aw-client

- Official `aw-watcher-window` is X11 only on Linux; `aw-watcher-afk` watches keyboard and mouse, 3 min default. https://docs.activitywatch.net/en/latest/watchers.html; https://raw.githubusercontent.com/ActivityWatch/aw-watcher-afk/master/README.md
- awatcher (Rust) replaces both on Wayland: wlr-foreign-toplevel for windows, ext-idle-notify for idle, Hyprland listed with Sway. Bundle build embeds aw-server-rust. TOML filters rewrite app or title by regex. https://raw.githubusercontent.com/2e3s/awatcher/main/README.md
- Hyprland implements both protocols: `src/protocols/ForeignToplevelWlr.cpp`, `src/protocols/IdleNotify.cpp`. https://github.com/hyprwm/Hyprland/tree/main/src/protocols
- Query model: `events = filter_period_intersect(flood(window_events), filter_keyvals(afk_events, "status", ["not-afk"]))`, then `categorize` by regex. https://raw.githubusercontent.com/ActivityWatch/aw-client/master/aw_client/queries.py
- Could awatcher plus ~100 lines of Python replace the plan's sensors? It replaces hypridle and the class/title half of the poller. It cannot see the kitty cwd (Claude overwrites the title) and knows nothing about agent beats. You still write the cwd sensor, the beat command, the REST client and run two extra daemons. Not simpler. Plan holds.

### WakaTime, wakapi, terminal plugins

- Heartbeats on file change, save, or every 2 min of activity; project from the git folder, override via `.wakatime-project`; offline queue `~/.wakatime/offline_heartbeats.bdb`. https://wakatime.com/help/creating-plugin; https://wakatime.com/faq; https://raw.githubusercontent.com/wakatime/wakatime-cli/develop/USAGE.md
- Duration = consecutive heartbeats within the keystroke timeout, default 15 min. https://wakatime.com/faq ("15 min timeout (default): Your dashboard shows 16 mins")
- wakapi: self-hosted, SQLite default, web dashboard plus REST, "partially compatible with WakaTime". https://raw.githubusercontent.com/muety/wakapi/master/README.md
- Terminal plugins: WakaTime itself says not to use them; bash activity books to a fixed `Terminal` project via `PROMPT_COMMAND`. https://wakatime.com/terminal (bash: https://github.com/gjsheep/bash-wakatime)
- Verdict: editor-centric heartbeats; kitty, Claude and pi are not editors; no idle sensor of its own; corrections through a web UI. Plan holds. Fix the "sums concurrent projects" wording (section 2 table).

### Idle daemons and protocols

- ext-idle-notify-v1: client asks for a notification with a timeout in ms, gets `idled` and `resumed`; v2 adds `get_input_idle_notification` that ignores inhibitors. Hyprland listed as implementing v2. Several clients can hold notifications at once, so hypridle beside quickshell's `IdleMonitor` is normal use. https://wayland.app/protocols/ext-idle-notify-v1
- hypridle: `general { lock_cmd, unlock_cmd, before_sleep_cmd, after_sleep_cmd, ignore_dbus_inhibit, ignore_systemd_inhibit }`, `listener { timeout, on-timeout, on-resume, condition_cmd, condition_retry }`; sleep hooks come from logind. https://raw.githubusercontent.com/hyprwm/hypridle/main/README.md
- swayidle: `timeout <s> <cmd> resume <cmd>`, `before-sleep`, `after-resume`, `lock`, `unlock`, `idlehint`, `-w`. Equivalent; hypridle is the ecosystem default. https://raw.githubusercontent.com/swaywm/swayidle/master/swayidle.1.scd
- logind: session `IdleHint=no`, `IdleSinceHint=0` here; neither Hyprland nor quickshell sets it. `PrepareForSleep(b)` signal exists on the system bus. `loginctl show-session self -p IdleHint -p IdleSinceHint`; `busctl introspect org.freedesktop.login1 /org/freedesktop/login1`
- systemd-sleep hooks: `/usr/lib/systemd/system-sleep/` scripts run as root with `pre|post`; the man page calls them "hacks" and points to inhibitor locks. `man 8 systemd-sleep`

### Storage

JSONL wins. `attribute()` is a stateful minute walk; SQL cannot express it, so sqlite would add a schema, inserts and a `SELECT ... ORDER BY ts` that returns the same list `read_events` already returns. Append is `f.write(json.dumps(e) + "\n")`. Keep section 4 as is.

## 5. Attribution model notes

| Model             | Rule                                                                                                                                                                     | Concurrency                                                                                                             | Unattended agents                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| WakaTime / wakapi | Consecutive heartbeats within a timeout (15 min WakaTime, 10 min wakapi) form one duration keyed by project hash                                                         | Sequential; a project switch closes the duration; interleaved projects never double count but lose the gap between them | Agent tools do not send heartbeats; not modelled                                                             |
| ActivityWatch     | Window events intersected with `not-afk` periods, `flood` fills small gaps, `categorize` by regex                                                                        | One focused window at a time; sum equals presence                                                                       | Not modelled; agent work in a background window is invisible                                                 |
| arbtt             | One sample per minute tagged by rules; `$idle > 300` tags inactive                                                                                                       | One focused window per sample                                                                                           | Not modelled                                                                                                 |
| plan.md section 8 | Present minute (not idle, poller heartbeat within 2 min) split evenly across repo buckets with a live signal: agent beat 10 min, focused kitty cwd or GitHub title 1 min | Sum per minute is exactly 1.0, so totals equal wall-clock presence; per-project split is explicit                       | Beats while idle book nothing; beats while present credit the repo even when the focused window is unrelated |

Pitfalls to keep in mind:

- A present user watching a video while Claude runs in `assets` credits `assets` for 10 min after each tool call. The plan accepts this (agent work is billable). Note it in README.
- Omarchy's screensaver window (`org.omarchy.screensaver`) can take focus at 150 s idle. With a 300 s hypridle timeout, minutes 2.5 to 5 of each idle stretch get `personal/other` (no title rule matches). Fix in section 6.
- Focus lines repeat every 60 s while `(class, title, cwd)` is stable, so a 1 min focus window on a stable kitty cwd never expires while it stays focused. Correct behaviour; keep the 60 s heartbeat.
- Latest appended span wins for overlaps. Deterministic; no gap in the model.
